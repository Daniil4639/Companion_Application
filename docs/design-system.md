# Design system

## Направление

Интерфейс первой версии — спокойный, практичный инструмент для ежедневного планирования. Основной визуальный язык строится на тёплой бумажной палитре. На первом этапе не показываем чат, портрет или аватар маскота и не превращаем рабочие экраны в фэнтезийную декорацию. Персонаж отложен до будущего этапа.

Референсы, которые пользователь выбирает для интерфейса, размещаются в `frontend/references/`. Они служат источником визуальных решений, а не требованием дословно копировать отдельный экран.

## Цветовые токены

Использовать эти значения как исходную палитру. Назначение токенов — предлагаемая систематизация; конкретные оттенки и контраст следует оценивать на реальных компонентах по мере сборки интерфейса.

| Токен | Цвет | Роль |
|---|---|---|
| `--color-parchment` | `#F2E6CC` | Основной светлый фон страницы |
| `--color-aged-paper` | `#D7BD90` | Вторичные поверхности, границы и выделение спокойных областей |
| `--color-terracotta` | `#A85B32` | Основной акцент: действия, активное состояние, важные маркеры |
| `--color-ink` | `#4A392E` | Основной текст и наиболее контрастные элементы |
| `--color-sage` | `#78836B` | Вторичный акцент: статусы, дополнительные маркеры |

Токены следует объявлять централизованно в CSS и использовать по смыслу, а не разносить произвольные HEX-значения по компонентам. Для состояний ошибки, успеха, фокуса и отключённого элемента можно добавить семантические оттенки, сохраняя общий тёплый характер; их значения пока не заданы.

## Иерархия и компоненты

- Расписание и задачи — главные разделы первой версии.
- Состояния задачи должны различаться не только цветом, но и текстом/меткой: «Запланирована», «В работе», «Готова» (окончательные подписи интерфейса можно уточнить при реализации).
- События календаря и карточки задач должны иметь ясную границу, читаемое название и заметное основное действие.
- Приоритет — плотности информации, сканируемости календаря и простому переносу задачи между этапами.
- Декор, анимация и тематические иллюстрации не должны мешать планированию.

## Типографика, размеры и адаптивность

Конкретные шрифты, шкала размеров, сетка, радиусы, тени и правила адаптивности пока не утверждены. Выбирать их по референсам и удобству чтения при создании интерфейса, затем оформлять как общие токены. Не считать стили из резервных макетов действующим стандартом: они принадлежат ранним экспериментам.

## Доступность

- Поддерживать достаточный контраст текста и элементов управления на бумажных фонах.
- Не кодировать статус только цветом.
- Обеспечить видимый фокус клавиатуры, понятные подписи элементов управления и читаемые размеры текста.
- Проверять календарь и Kanban при обычном масштабе и на узком окне.
