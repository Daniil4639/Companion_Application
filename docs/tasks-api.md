# Задачи и Kanban

## Запуск и хранение

Запуск из корня проекта: `python -m backend.app.main`. На главной странице выберите «Задачи».
Миграция `f4a0c6d13982` добавляет независимую таблицу tasks. Данные событий и профиля не изменяются. Миграция применяется при запуске. Откат этой миграции удаляет таблицу задач.

Идентификатор — UUID, как у событий. Название обязательно, до 255 символов; описание необязательно, до 10 000 символов. Статусы: BACKLOG, TODO, IN_PROGRESS, DONE. В UI: «Идеи», «К выполнению», «В работе», «Готово». Приоритеты API: Low, Medium, High; по умолчанию Medium. Новая задача по умолчанию попадает в конец BACKLOG.

scheduled_date и due_date — даты YYYY-MM-DD без времени, обе могут быть null. Они не переводятся между часовыми поясами. Плановая дата может оказаться позже дедлайна — например, для уже просроченной задачи. Аудитные даты created_at, updated_at и completed_at хранятся в UTC.

## API

| Метод | Путь | Результат |
|---|---|---|
| GET | /api/tasks | Список, 200 |
| POST | /api/tasks | Созданная задача, 201 |
| GET | /api/tasks/{id} | Задача, 200 |
| PATCH | /api/tasks/{id} | Обновлённая задача, 200 |
| DELETE | /api/tasks/{id} | 204 без тела |
| PATCH | /api/tasks/{id}/move | Перемещённая задача, 200 |

GET поддерживает status, priority, scheduled_date, due_date, date_from, date_to, limit (1–500, по умолчанию 100), offset (от 0). date_from/date_to задают включительный диапазон: в него должна попасть хотя бы одна из двух дат задачи. Совпадение обеих дат не дублирует запись. Сортировка: фиксированный порядок статусов, затем position. Остальные фильтры объединяются условием AND.

POST принимает title, description, status, priority, position, scheduled_date, due_date. PATCH принимает любое подмножество этих полей. description и даты очищаются через null. title, status, priority, position в PATCH не могут быть null. Аудитные поля и id менять нельзя; неизвестные поля отклоняются. Отсутствующая задача — 404, неверные данные — 422, конфликт ограничений — 409, занятая SQLite — 503.

Пример перемещения:

```json
{"status": "IN_PROGRESS", "position": 0}
```

position — конечный индекс с нуля внутри целевой колонки после исключения перемещаемой карточки. Индекс за концом колонки означает добавление в конец. Изменение статуса через обычный PATCH без position также добавляет карточку в конец. Оставшиеся позиции уплотняются до 0..N-1 после перемещения и удаления.

## Транзакции и будущий MCP

TaskService в backend/app/services/tasks.py не зависит от HTTP и интерфейса. Он принимает DTO и отдельную AsyncSession. Для изменяющей операции нужна свежая сессия без уже открытой транзакции: сервис сам начинает транзакцию, получает резервирование записи SQLite до чтения и фиксирует результат либо откатывает всё при ошибке.

Порядок защищён уникальностью (status, position). Перестановка проходит через временные свободные позиции внутри той же транзакции, чтобы не нарушать немедленные ограничения SQLite. Одновременные записи сериализуются. Для редактирования одной задачи из нескольких окон действует принцип последнего сохранения; версионность не входит в MVP.

При входе в DONE устанавливается completed_at; выход сбрасывает его. Редактирование или перестановка внутри DONE сохраняет момент завершения. Возвращение в DONE устанавливает новый момент.

## Интерфейс и календарь

Доска поддерживает перетаскивание в колонку, перед карточкой и после неё. Длинные колонки и доска прокручиваются. Для клавиатуры и сенсорного экрана доступны кнопки ↑/↓, а смена статуса — через форму. Сохранение происходит без перезагрузки страницы. При ошибке загрузки устаревшая доска блокируется до успешного обновления.

В недельной таблице отдельной строки задач нет. Правая панель показывает задачи на сегодня: «План» для scheduled_date, «Срок» для due_date. Совпадение дат не дублирует карточку или счётчик. Открывается та же задача по UUID; после сохранения обновляются обе проекции. Задачи на сегодня также видны в правой панели, даты отмечаются в мини-календаре. Выполненные задачи остаются видны с зачёркнутым названием. События не создаются, endpoint /api/schedule сохраняет свой прежний контракт.

Файлы UI: tasks-api.js, task-dialog.js, tasks.js, tasks.css. В прямом предпросмотре HTML доска пустая, изменения недоступны.

`python -m unittest discover -s tests -v`
