# Локальный профиль

Один профиль на установленное приложение, без пароля и процедуры входа. Это персональные настройки, а не механизм ограничения доступа к API. Существующие события остаются в общей локальной базе, добавление владельца к каждой серии пока не требуется.

## Данные

`users`: id (всегда 1), username (1–64 символа после удаления пробелов по краям), display_name (до 128 символов или null), timezone (IANA, до 64), timezone_mode (system/manual), locale (пока только ru-RU), created_at и updated_at (UTC).

Отдельная миграция `e3f9b5c02871` создаёт таблицу без изменения событий. Она применяется при следующем запуске приложения. Профиль автоматически не создаётся. Ограничение `id = 1` защищает единственность записи и при конкурентных запросах.

## HTTP

- `GET /user`: профиль или 404.
- `POST /user`: создать профиль, 201; если уже существует — 409.
- `PATCH /user`: частичное изменение, 200; без профиля — 404.
- Неверные значения, неизвестные поля, null для обязательных полей — 422. display_name можно очистить через null или пустую строку.
- `GET /` и `/templates/index.html`: экран первого запуска при отсутствии профиля, календарь при наличии.
- `GET /welcome` и `/templates/welcome.html`: первый запуск; при наличии профиля перенаправляют на календарь.

Сервис не зависит от HTTP. Запись использует существующий механизм транзакций приложения.

## Часовой пояс

В `system` браузер определяет пояс устройства. Поле недоступно для редактирования. Сохранённый timezone — снимок пояса при последнем сохранении профиля; эффективный пояс определяется заново при загрузке. При возвращении в приложение после изменения пояса ОС страница перезагружается.

В `manual` используется сохранённое значение. Поле предлагает IANA-зоны и допускает ввод вручную; сервер проверяет значение через ZoneInfo. Смена пояса перезагружает календарь и меняет дни, подписи, границы запросов расписания и интерпретацию вводимого времени. UTC-моменты существующих событий не переписываются; пояс повторения серии сохраняется.

`timezone.js` отделяет календарные компоненты от реальных моментов времени: CalendarDate хранит компоненты в UTC-полях, а toISOString преобразует их в UTC-момент выбранной зоны. Это устраняет влияние переходов часов в зоне ОС при ручном выборе другого пояса. Несуществующее время в форме отклоняется. Для двусмысленного времени осеннего перехода выбран первый вариант; неизменённые значения существующих событий сохраняют исходный UTC-момент. Отдельный переключатель варианта перехода пока отсутствует.

Имя, режим пояса и язык доступны в «Настройках». Язык сейчас ограничен русским. Прямой просмотр HTML остаётся демонстрационным, профиль в нём не сохраняется.
