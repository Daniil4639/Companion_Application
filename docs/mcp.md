# MCP: локальный доступ к задачам и расписанию

Реализован официальный Python MCP SDK `mcp==2.3.0`. Сервер работает внутри FastAPI, транспорт — Streamable HTTP, адрес по умолчанию — `http://127.0.0.1:8181/mcp`. Конечный `/` также допустим. Доступны пять инструментов чтения и двенадцать инструментов записи; изменения сохраняются сразу.

## Запуск

Из корня проекта, в Python-окружении приложения:

```powershell
python -m pip install -r requirements.txt
python -m backend.app.main
```

Приложение выполняет существующие Alembic-миграции, затем запускает менеджер MCP. При остановке закрывает MCP и пул БД. Порт берётся из `APP_PORT` (по умолчанию 8181), база — из существующих настроек приложения.

Для запуска через Uvicorn напрямую сохраняйте локальную привязку и отключённую обработку прокси-заголовков:

```powershell
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8181 --no-proxy-headers
```

## Инструменты

`tasks_list(status=null, limit=100, offset=0)` возвращает `{ "tasks": [...], "next_offset": null }`. У каждой задачи: `id`, `title`, `status`, `priority`, `scheduled_date`, `due_date`. Статус — `BACKLOG`, `TODO`, `IN_PROGRESS` или `DONE`; отсутствие фильтра означает все статусы. Размер страницы — от 1 до 500. Если `next_offset` не `null`, передайте его как следующий `offset`, сохранив остальные параметры. Порядок определяет существующий TaskService. При изменении доски между страницами начните чтение заново: несколько вызовов не образуют единый снимок базы.

`schedule_list(range_start, range_end)` возвращает `{ "occurrences": [...] }`. Это те же экземпляры событий, что в `/api/schedule`: ID серии, исходное начало, фактические начало и конец, название, описание и категория. Период включает начало и исключает конец; возвращаются пересекающие его события. Даты входа должны содержать UTC-смещение; ответ содержит UTC. Максимум — 366 дней, действуют ограничения существующего календарного сервиса на число серий и экземпляров. Задачи не превращаются в события: они доступны через `tasks_list`.

Повторяемость, переходы летнего/зимнего времени, отмены и переносы обрабатывает CalendarService. Адаптер не содержит SQL-запросов и не копирует доменные правила. Каждый вызов использует отдельную сессию через существующий `get_db`; сессия закрывается и при ошибке. Ошибки аргументов и доменной валидации возвращаются как MCP tool error; детали ошибок БД не передаются клиенту.

## Инструменты записи

Аргументы создания, изменения и перемещения передаются объектом `data`, ID существующей задачи — отдельным `task_id` (UUID). Ответ задач — полный TaskResponse, включая position и completed_at; ответ создания события — EventResponse.

| Инструмент | Аргументы | Действие |
| --- | --- | --- |
| tasks_create | data: TaskCreate | Создаёт задачу; по умолчанию BACKLOG, Medium, без дат, в конце колонки |
| tasks_update | task_id, data: TaskPatch | Меняет только переданные поля; null очищает description, scheduled_date, due_date |
| tasks_move | task_id, data: {status, position} | Атомарно перемещает и упорядочивает карточки; position начинается с 0 |
| tasks_complete | task_id | Переводит в DONE и устанавливает completed_at |
| schedule_create | data: SingleEventCreate | Создаёт обычное событие; recurrence_rule допускает только null или отсутствие |

tasks_update использует тот же DTO, что REST PATCH, включая status/position; для перемещения предпочтителен tasks_move. Повторный tasks_complete сохраняет completed_at и позицию уже завершённой задачи, но сервис обновляет updated_at. Возврат из DONE через tasks_move сбрасывает completed_at. Позиция за пределами колонки означает добавление в конец.

Примеры аргументов для Inspector:

**tasks_create**
```json
{"data": {"title": "Подготовить план", "priority": "High", "status": "TODO", "scheduled_date": "2026-10-26"}}
```

В следующих вызовах замените UUID на id из результата создания.

**tasks_update**
```json
{"task_id": "11111111-1111-1111-1111-111111111111", "data": {"description": "Черновик плана", "due_date": null}}
```

**tasks_move**
```json
{"task_id": "11111111-1111-1111-1111-111111111111", "data": {"status": "IN_PROGRESS", "position": 0}}
```

**tasks_complete**
```json
{"task_id": "11111111-1111-1111-1111-111111111111"}
```

**schedule_create**
```json
{"data": {"title": "Обсуждение плана", "start_at": "2026-10-26T15:00:00+03:00", "finish_at": "2026-10-26T16:00:00+03:00", "timezone": "Europe/Moscow", "category": "default"}}
```

TaskService сам управляет транзакциями записи задач. Для календаря адаптер открывает write_transaction, как REST-обработчик, и вызывает CalendarService.create_event. Новых доменных методов не требуется.

Инструменты записи объявлены с readOnlyHint=false; изменение существующих задач — с destructiveHint=true, поскольку может перезаписать значения. Все записи имеют idempotentHint=false: повторное создание добавляет ещё одну запись, а редактирование обновляет аудитное время. Аннотации описывают поведение и не являются механизмом подтверждения. После потери ответа на запись сначала проверьте состояние, прежде чем повторять вызов. Редактирование обычных событий и отдельных вхождений, получение полной информации и безопасное удаление описаны в [mcp-calendar-editing.md](mcp-calendar-editing.md). Правила повторения, разделение, восстановление, предпросмотр и контекст времени описаны в [mcp-recurrence.md](mcp-recurrence.md). Создание повторяющихся серий через schedule_create и удаление всей серии пока недоступны.

## Проверка через MCP Inspector

Нужны Node.js версии 22.19 или новее и запущенное приложение. Запустите [официальный Inspector](https://github.com/modelcontextprotocol/inspector):

```powershell
npx @modelcontextprotocol/inspector
```

1. Откройте локальный адрес, напечатанный Inspector в терминале.
2. Добавьте подключение с транспортом **Streamable HTTP** и URL `http://127.0.0.1:8181/mcp`. Используйте локальный backend Inspector для соединения; прямой браузерный CORS-доступ приложение не включает. Токен приложения не требуется.
3. Подключитесь и откройте **Tools**. Список должен содержать 17 инструментов: пять для чтения и двенадцать для записи.
4. Вызовите `tasks_list` с `{}` либо с такими параметрами:

```json
{ "status": "TODO", "limit": 100, "offset": 0 }
```

5. Вызовите `schedule_list`, выбрав период, в котором в вашем календаре есть события:

```json
{
  "range_start": "2026-10-26T00:00:00+03:00",
  "range_end": "2026-11-02T00:00:00+03:00"
}
```

6. Сравните результат с интерфейсом приложения. Измените задачу или перенесите экземпляр события в интерфейсе, повторите вызов инструмента и проверьте обновлённые данные. Пустой список при отсутствии подходящих записей — нормальный результат.

## Границы доступа

Сервер привязан к `127.0.0.1`. На `/mcp` дополнительно проверяются адрес соединения, единственный локальный `Host` и, если он передан, локальный HTTP `Origin`. Запросы с `Forwarded`, `X-Forwarded-*` или `X-Real-IP` отклоняются с 403. SDK также включает защиту от DNS rebinding и разрешает Host/Origin только для localhost или 127.0.0.1 на настроенном APP_PORT. При запуске через Uvicorn параметр --port должен совпадать с APP_PORT. Максимальный размер MCP-запроса — 64 КиБ.

Доверенная граница — локальная машина, а не отдельный пользователь ОС: другие локальные процессы могут читать и изменять данные. Не публикуйте этот endpoint через туннель или reverse proxy; прокси, скрывающий удалённый источник, невозможно надёжно отличить от локального клиента. Для удалённого доступа потребуется отдельная аутентификация и новая политика доступа. Локальный backend Inspector выступает доверенным MCP-клиентом.

## Автоматические проверки

```powershell
python -m pip install -r requirements-dev.txt
python -B -m unittest discover -s tests -v
```

`tests/test_mcp.py` запускает настоящий HTTP-сервер на свободном loopback-порту и использует официальный MCP-клиент. Проверяются обнаружение инструментов, совместимость legacy-протокола, реальные записи SQLite через REST, фильтрация/пагинация, DST и исключения, ошибки, создание и редактирование задач, перемещения и completed_at, создание обычных событий, откат записей при сбое, параллельные сессии, освобождение соединений и запрет удалённых запросов. Тесты работают с временными базами, не с пользовательской базой.
