# MCP: локальный доступ к задачам и расписанию

Реализован официальный Python MCP SDK `mcp==2.3.0`. Сервер работает внутри FastAPI, транспорт — Streamable HTTP, адрес по умолчанию — `http://127.0.0.1:8181/mcp`. Конечный `/` также допустим. Запись данных через MCP не предусмотрена.

## Запуск

Из корня проекта, в Python-окружении приложения:

```powershell
python -m pip install -r requirements.txt
python -m backend.app.main
```

Приложение выполняет существующие Alembic-миграции, затем запускает менеджер MCP. При остановке закрывает MCP и пул БД. Порт берётся из `APP_PORT` (по умолчанию 8181), база — из существующих настроек приложения.

Для запуска через Uvicorn напрямую сохраняйте локальную привязку и отключённую обработку прокси-заголовков:

```powershell
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8181 --no-proxy-headers
```

## Инструменты

`tasks_list(status=null, limit=100, offset=0)` возвращает `{ "tasks": [...], "next_offset": null }`. У каждой задачи: `id`, `title`, `status`, `priority`, `scheduled_date`, `due_date`. Статус — `BACKLOG`, `TODO`, `IN_PROGRESS` или `DONE`; отсутствие фильтра означает все статусы. Размер страницы — от 1 до 500. Если `next_offset` не `null`, передайте его как следующий `offset`, сохранив остальные параметры. Порядок определяет существующий TaskService. При изменении доски между страницами начните чтение заново: несколько вызовов не образуют единый снимок базы.

`schedule_list(range_start, range_end)` возвращает `{ "occurrences": [...] }`. Это те же экземпляры событий, что в `/api/schedule`: ID серии, исходное начало, фактические начало и конец, название, описание и категория. Период включает начало и исключает конец; возвращаются пересекающие его события. Даты входа должны содержать UTC-смещение; ответ содержит UTC. Максимум — 366 дней, действуют ограничения существующего календарного сервиса на число серий и экземпляров. Задачи не превращаются в события: они доступны через `tasks_list`.

Повторяемость, переходы летнего/зимнего времени, отмены и переносы обрабатывает CalendarService. Адаптер не содержит SQL-запросов и не копирует доменные правила. Каждый вызов использует отдельную сессию через существующий `get_db`; сессия закрывается и при ошибке. Ошибки аргументов и доменной валидации возвращаются как MCP tool error; детали ошибок БД не передаются клиенту.

## Проверка через MCP Inspector

Нужны Node.js версии 22.19 или новее и запущенное приложение. Запустите [официальный Inspector](https://github.com/modelcontextprotocol/inspector):

```powershell
npx @modelcontextprotocol/inspector
```

1. Откройте локальный адрес, напечатанный Inspector в терминале.
2. Добавьте подключение с транспортом **Streamable HTTP** и URL `http://127.0.0.1:8181/mcp`. Используйте локальный backend Inspector для соединения; прямой браузерный CORS-доступ приложение не включает. Токен приложения не требуется.
3. Подключитесь и откройте **Tools**. Список должен содержать ровно `tasks_list` и `schedule_list`.
4. Вызовите `tasks_list` с `{}` либо с такими параметрами:

```json
{ "status": "TODO", "limit": 100, "offset": 0 }
```

5. Вызовите `schedule_list`, выбрав период, в котором в вашем календаре есть события:

```json
{
  "range_start": "2026-10-26T00:00:00+03:00",
  "range_end": "2026-11-02T00:00:00+03:00"
}
```

6. Сравните результат с интерфейсом приложения. Измените задачу или перенесите экземпляр события в интерфейсе, повторите вызов инструмента и проверьте обновлённые данные. Пустой список при отсутствии подходящих записей — нормальный результат.

## Границы доступа

Сервер привязан к `127.0.0.1`. На `/mcp` дополнительно проверяются адрес соединения, единственный локальный `Host` и, если он передан, локальный HTTP `Origin`. Запросы с `Forwarded`, `X-Forwarded-*` или `X-Real-IP` отклоняются с 403. SDK также включает защиту от DNS rebinding. Максимальный размер MCP-запроса — 64 КиБ.

Доверенная граница — локальная машина, а не отдельный пользователь ОС: другие локальные процессы могут читать данные. Не публикуйте этот endpoint через туннель или reverse proxy; прокси, скрывающий удалённый источник, невозможно надёжно отличить от локального клиента. Для удалённого доступа потребуется отдельная аутентификация и новая политика доступа. Локальный backend Inspector выступает доверенным MCP-клиентом.

## Автоматические проверки

```powershell
python -m pip install -r requirements-dev.txt
python -B -m unittest discover -s tests -v
```

`tests/test_mcp.py` запускает настоящий HTTP-сервер на свободном loopback-порту и использует официальный MCP-клиент. Проверяются обнаружение инструментов, совместимость legacy-протокола, реальные записи SQLite через REST, фильтрация/пагинация, DST и исключения, ошибки, параллельные сессии, освобождение соединений и запрет удалённых запросов. Тесты работают с временными базами, не с пользовательской базой.
