# MCP Client Runtime и каталог подключений

Folliant содержит MCP-сервер и независимый MCP-клиент в одном процессе FastAPI. Клиент использует официальный SDK 2.3.0 и обращается к серверу по настоящему Streamable HTTP, а не к Python-сервисам. Он не открывает SQLAlchemy-сессии и не обращается к SQLite.

## Компоненты

- `backend/app/mcp_client/manager.py` — MCPClientManager: регистрация, соединения, обнаружение инструментов, последовательные вызовы и закрытие.
- `registry.py` — ToolRegistry: каталог по ключу `server_id.tool_name`, описание, входная/выходная JSON Schema, аннотации и доступность. На сервер передаётся оригинальное имя. Точка запрещена в server_id, поэтому пространства имён не пересекаются.
- `executor.py` — ToolExecutor: проверка доступности, валидация JSON Schema и структурированный результат выполнения.
- `models.py` — типы конфигурации, записей каталога и результатов.
- `backend/app/services/mcp_servers.py` — MCPServerService: единственная точка SQL-доступа к определениям подключений. Сервис владеет короткими сессиями БД, защищает внутреннее подключение и согласует изменения конфигурации с менеджером.
- `backend/app/models/mcp_server.py` — таблица `mcp_servers`; в ней нет инструментов, сетевых сессий или разрешений чатов.
- `backend/app/api/mcp_servers_router.py` — локальный HTTP API управления для будущего интерфейса.

Приложение создаёт компоненты в lifespan: `app.state.mcp_clients`, `app.state.tool_registry`, `app.state.tool_executor`, `app.state.mcp_catalog`. При импорте модулей и регистрации конфигураций сетевых соединений нет. После миграций сервис создаёт внутреннюю запись, `read_all()` возвращает конфигурации для менеджера. Обнаружение инструментов запускается фоновой задачей `app.state.mcp_discovery`; для Folliant она сначала ждёт открытия локального HTTP-порта (до 10 секунд). Недоступность внешнего сервера не мешает запуску приложения. Постоянного опроса и автоматических переподключений нет: повторить обнаружение можно явно.

## Хранение подключений

Конфигурации хранятся в SQLite. `MCP_SERVERS` и отдельный MCP env-файл больше не используются. Старые внешние подключения из env автоматически не импортируются: добавьте их через HTTP API. Общий `.env` приложения остаётся для `APP_PORT`, `DATABASE_URL` и других общих настроек.

Новая миграция `d4e2819c6a10` добавляет только таблицу `mcp_servers`; календарь и задачи не меняются. Она выполняется существующим механизмом миграций при запуске. Внутренняя запись `folliant` создаётся приложением, а не миграцией, поскольку её адрес зависит от `APP_PORT`.

`folliant` имеет `is_internal=true`, адрес `http://127.0.0.1:<APP_PORT>/mcp` и не допускает пользовательского редактирования/удаления. Приложение само обновляет её адрес при смене порта. Переданный Uvicorn порт должен соответствовать APP_PORT (по умолчанию 8181). Ограничение БД связывает зарезервированный ID с внутренним признаком; API не принимает `is_internal` от клиента.

Внешнее подключение создаётся, например, таким запросом `POST /api/mcp/servers`:

```json
{
  "id": "notes",
  "name": "Notes MCP",
  "transport": "streamable_http",
  "url": "http://127.0.0.1:9000/mcp",
  "connect_timeout": 10,
  "operation_timeout": 30
}
```

ID уникален, неизменяем и содержит только латинские буквы, цифры, `_`, `-` (1–64 символа). Поля ответа дополнительно содержат `is_internal`, `created_at`, `updated_at`. Переключателя enabled нет: выбор серверов для конкретного чата будет отдельной функцией.

Поддерживаются HTTP/HTTPS и Streamable HTTP. URL не может содержать пароль, query-параметры, фрагмент или пробелы. Авторизационные токены пока не поддерживаются. Добавляйте только доверенные адреса: проверка подключения выполняет исходящий запрос с компьютера пользователя.

## HTTP API для настроек

Все пути ниже начинаются с `/api/mcp/servers`. Доступ ограничен прямым localhost-соединением с проверкой Host, Origin и запретом forwarded-заголовков по существующей политике MCP. Произвольного вызова инструмента через HTTP API нет.

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | пустой | Сохранённые подключения, без сетевых запросов |
| POST | пустой | Создание внешнего подключения, 201 |
| GET | `/{id}` | Определение подключения |
| PATCH | `/{id}` | Изменение name, url, connect_timeout, operation_timeout |
| DELETE | `/{id}` | Удаление внешнего подключения, 204 |
| GET | `/{id}/status` | server_id, state, available_tools, last_error |
| GET | `/{id}/tools` | Кэш инструментов, без запроса к серверу |
| POST | `/{id}/test` | Реальное соединение/обновление tools; ответ со статусом |
| POST | `/{id}/refresh-tools` | Обновлённый список инструментов |

Состояния: disconnected, connecting, connected, closing. Это последнее известное состояние, не непрерывная проверка доступности. `last_error` содержит безопасные code/message/protocol_code без текста удалённого исключения.

Сохранение выполняется независимо от доступности сервера. После создания или редактирования выполните test/refresh-tools, чтобы получить актуальный каталог; до этого новое подключение не содержит доступных tools. PATCH не принимает пустое тело, null, id, transport или is_internal. Даже изменение имени внутреннего сервера запрещено.

Ошибки: 404 — неизвестный ID; 403 — внутреннее подключение или отказ политики доступа; 409 — дубликат ID, завершение приложения или временно закрывающееся подключение; 422 — некорректные данные; 502 — ошибка соединения/протокола; 504 — тайм-аут. У сетевых ошибок `detail` — объект с code/message/protocol_code. Ошибка test/refresh не удаляет сохранённую запись.

При PATCH/DELETE сервис сначала запрещает новые вызовы и ждёт уже принятые, **не удерживая сессию БД**. Затем выполняет SQL-транзакцию, меняет регистрацию менеджера и удаляет старый кэш tools. Если запись не удалась, прежняя конфигурация остаётся, соединение можно открыть заново. Отмена HTTP-запроса не прерывает начатую операцию изменения каталога; shutdown дожидается таких операций. Изменения каталога сериализованы в рамках одного процесса. Приложение рассчитано на один процесс Uvicorn; синхронизация runtime между несколькими worker-процессами не реализована.

Тайм-аут подключения включает инициализацию протокола. operation_timeout ограничивает обнаружение каталога и выполнение одного запроса после его извлечения из очереди; время ожидания в очереди в него не входит. Значения задаются в секундах и должны быть положительными.

## Использование в backend

В асинхронном коде после готовности HTTP-сервера, без открытой транзакции БД:

```python
manager = app.state.mcp_clients
await manager.connect("folliant")
tools = app.state.tool_registry.list("folliant")

result = await app.state.tool_executor.execute(
    "folliant.tasks_list", {"status": "TODO"}
)
print(result.status)
```

`connect` на уже открытом соединении не выполняет проверку сети. `state(server_id)` отражает известное состояние соединения, а не постоянный health-check. Для актуализации каталога используйте `await manager.refresh_tools(server_id)`. Обновление атомарно заменяет каталог сервера после получения всех страниц; удалённые инструменты исчезают. При ошибке/отключении сохранённые записи становятся недоступными. `await manager.reconnect(server_id)` закрывает прежнюю сессию, создаёт новую и заново обнаруживает инструменты.

Самостоятельно созданный менеджер необходимо закрывать в finally через `await manager.aclose()`. Менеджер привязан к своему жизненному циклу и event loop; после aclose создайте новый экземпляр. Менеджер FastAPI закрывается автоматически.

## Жизненный цикл и конкурентность

На каждый сервер создаётся одна задача-владелец сессии. Она входит в SDK-контекст, последовательно читает команды из очереди и сама выходит из контекста. Это соблюдает ограничения AnyIO: нельзя открыть контекст в одном запросе FastAPI, а закрыть в другом.

Очередь ограничена 100 ожидающими командами. Переполнение возвращает unavailable. Разные серверы обслуживаются независимыми задачами. При disconnect/shutdown новые команды отклоняются, уже принятые завершаются в порядке очереди с индивидуальными тайм-аутами, затем сессия закрывается. Поэтому shutdown может ждать сумму времени принятых операций. Runtime закрывается до остановки менеджера MCP-сервера и освобождения пула БД. Если HTTP-listener уже остановлен внешним ASGI-сервером, неуспевшие сетевые операции завершаются ошибкой или по тайм-ауту, а не ожидают бесконечно.

Отмена ожидающего Python-клиента не отменяет уже принятую команду: инструмент записи мог начать менять данные. При тайм-ауте/ошибке транспорта соединение закрывается, каталог помечается недоступным. Автоматической повторной отправки инструмента нет. Используется `Client.session.call_tool`, чтобы не включать высокоуровневые циклы повторов/elicitation SDK. После неопределённого сбоя записи сначала перечитайте состояние сервера.

## Результаты и доверие

ToolExecutor возвращает ExecutionResult с tool_id, status, result и error:

| status | Значение |
| --- | --- |
| success | Успешный MCP-результат |
| tool_error | Сервер вернул isError=true; исходный результат сохранён |
| protocol_error | Ошибка JSON-RPC/MCP, некорректный ответ или схема |
| connection_error | Обрыв или ошибка транспорта |
| timeout | Истёк лимит ожидания; исход записи может быть неизвестен |
| invalid_arguments | Аргументы не соответствуют JSON Schema |
| unknown_tool | Нет записи в каталоге |
| unavailable | Отключённый сервер, закрытие, переполненная очередь или недоступный инструмент |
| permission_denied | Отказ подключённой локальной политики |

result содержит полный сериализованный CallToolResult SDK: content, structuredContent, isError и metadata. Текст, изображения, аудио, ссылки и встроенные ресурсы не сводятся к одной строке. error содержит безопасное описание, код категории и при наличии числовой код протокола. Сетевой сбой, при котором SDK не успел получить ответ до дедлайна, может классифицироваться как timeout.

Аргументы валидируются установленным jsonschema; локальные `$ref` поддерживаются, загрузка удалённых/файловых схем запрещена. Описания, аннотации и результаты сторонних серверов — недоверенные данные. Runtime не исполняет их как код и не формирует из них системные инструкции. Tool Annotations не являются разрешением на вызов.

Для будущего PermissionManager есть необязательный асинхронный hook `ToolExecutor(manager, authorize=policy)`, принимающий запись инструмента и аргументы и возвращающий bool. Без него доступ разрешён к инструментам явно настроенных серверов. Пользовательских подтверждений пока нет. Публичный REST endpoint произвольного выполнения не добавлен.

Логгер `character_helper` пишет JSON-события подключения, обнаружения, начала/завершения/ошибки вызова и отключения. Поля: server_id, имя инструмента, длительность, категория ошибки; аргументы, результаты, URL и удалённые тексты исключений не логируются этим компонентом.

## Ручная диагностика

Запустите приложение в первом терминале:

```powershell
python -m backend.app.main
```

Из корня проекта во втором терминале:

```powershell
python -m scripts.check_mcp_client
```

Скрипт читает подключения через MCPServerService из той же SQLite (DATABASE_URL должен совпадать с приложением), закрывает SQL-сессию и подключается к серверу `folliant`, печатает обнаруженные инструменты, выполняет tasks_list и выводит полный результат, затем закрывает соединение. Вывод содержит реальные задачи — это явная диагностическая операция, а не фоновое логирование. При ошибке возвращается ненулевой exit code и диагностическое сообщение.

## Автоматические проверки

```powershell
python -B -m unittest discover -s tests -v
```

`tests/test_mcp_client.py` использует настоящий Uvicorn/MCP на свободном localhost-порту и временные базы. Проверяются чтение задач/расписания, передача аргументов, пространства имён, JSON Schema, tool error, JSON-RPC error по HTTP, недоступность, тайм-аут без повтора, обновление каталога, переподключение, сохранение контента, отмена ожидающей задачи и shutdown с активными операциями. Диагностический скрипт отдельно запускается дочерним Python-процессом против тестового сервера.


## Будущие чаты

ToolRegistry — общий кэш обнаруженных инструментов. Для чата потребуется список выбранных server_id; из Registry можно взять `list(server_id)` для каждого разрешённого сервера. Проверка выбора чата должна выполняться и перед вызовом через `ToolExecutor.authorize`, а не только при составлении списка для модели. Наличие инструмента в кэше и Tool Annotations сами по себе не являются разрешением. Повторять list_tools на каждом сообщении чата не требуется.

При добавлении связи чатов с подключениями следует удалять связь вместе с удаляемым подключением, чтобы повторное создание того же ID не давало новому серверу старых разрешений. В этой итерации таблиц чатов и полноценной политики разрешений нет.

`tests/test_mcp_catalog.py` дополнительно проверяет CRUD, защиту Folliant, офлайн-сохранение, обновление/очистку кэша, локальную защиту API, ожидание активного инструмента без SQL-транзакции, отмену ожидающего клиента и сохранение конфигураций между экземплярами сервиса. Миграционные тесты проверяют обновление существующей базы без потери событий.
